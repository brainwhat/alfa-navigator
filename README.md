# Альфа.Навигатор — конкурсный демонстрационный прототип

Работающий демонстрационный **сквозной кредитный конвейер** для малого бизнеса. Клиентский кабинет, финансовый симулятор, банковская очередь, модель правил, альтернативное предложение, уточнение данных и журнал событий. **Только синтетические данные, никаких реальных кредитных решений.**

## Запуск

Требуется Docker с Compose.

```bash
docker compose up --build
```

Откройте http://localhost:8000. Демо-пароль по умолчанию: `alfa-demo-2026`; при входе выберите роль. OpenAPI: http://localhost:8000/docs. Проверка здоровья: `/api/health`.

Локально без Docker: `pip install -r requirements.txt && uvicorn app.main:app --reload`.

## Деплой на Vercel через GitHub Actions

Демо: https://alfa-navigator-gamma.vercel.app

Приложение работает на Vercel как одна Python-функция: [api/index.py](api/index.py) импортирует FastAPI-приложение, а [vercel.json](vercel.json) направляет на неё все пути. Деплоит только GitHub runner, автодеплой из Git-интеграции Vercel выключен (`git.deploymentEnabled: false`).

Пайплайн [.github/workflows/ci.yml](.github/workflows/ci.yml):

1. **test**: pytest, затем приложение запускается на runner'е и проходит smoke-тест [scripts/smoke.py](scripts/smoke.py) (вход → заявка → скоринг → принятие).
2. **deploy** (после test): `vercel pull` → `vercel build` → `vercel deploy --prebuilt`, затем smoke-проверка задеплоенного URL. Push в `main` выкатывает production, PR из этого репозитория выкатывает preview. Ручной запуск: Actions → CI/CD → Run workflow.

Разовая настройка:

1. Создайте проект на Vercel и привяжите его локально: `npx vercel link`. ID появятся в `.vercel/project.json`.
2. Создайте токен: Vercel → Account Settings → Tokens.
3. Добавьте в GitHub (Settings → Secrets and variables → Actions) секреты `VERCEL_TOKEN`, `VERCEL_ORG_ID` (поле `orgId`) и `VERCEL_PROJECT_ID` (поле `projectId`).
4. Задайте в Vercel → Project → Settings → Environment Variables (Production) свои `DEMO_CLIENT_KEY`, `DEMO_BANK_KEY`, `DEMO_CLIENT_PASSWORD`, `DEMO_BANK_PASSWORD`, а пароли продублируйте в GitHub Secrets для smoke-проверки. На production с демо-значениями из репозитория приложение не запустится. Локально и в preview работают значения по умолчанию.
5. По желанию: Vercel закрывает уникальные URL деплоев авторизацией (Deployment Protection). Production проверяется по публичному алиасу, а smoke-проверка preview пропускается с предупреждением. Чтобы preview тоже проверялись, включите Protection Bypass for Automation и положите его значение в секрет `VERCEL_AUTOMATION_BYPASS_SECRET`.

**База данных.** Если задан `DATABASE_URL` (или `POSTGRES_URL`), приложение работает с Postgres, иначе с SQLite по пути `DB_PATH`. На Vercel к проекту подключён Neon из Vercel Marketplace (бесплатный тариф, регион `iad1`), он сам выставляет `DATABASE_URL` для всех окружений. Таблицы создаются при первом старте. Локальный запуск, Docker и тесты по умолчанию используют SQLite. Проверить, какая база используется: `GET /api/health` возвращает поле `database`.

Preview-деплои подключены к той же базе, что и production.

## Быстрый e2e-тест

1. В клиентском кабинете введите данные кофейни. В симуляторе меняйте сумму и срок.
2. Войдите как предприниматель и отправьте заявку на 5 млн ₽ при потоке 240 тыс. ₽/мес. и существующих платежах 30 тыс. ₽. Под формой показывается предварительная оценка по тем же правилам, что и скоринг банка (`POST /api/precheck`, ничего не сохраняет). Если условия не проходят, у предложенных вариантов есть кнопка **Подать с этими условиями**.
3. Выйдите и войдите с ролью **Кабинет банка** — выберите ту же заявку. Очередь можно фильтровать по статусу, сумме, компании или номеру, по умолчанию срочные заявки сверху. Для заявок, ждущих банк, показывается время до конца SLA (24 ч, меняется переменной `BANK_SLA_HOURS`); нарушения подсвечиваются. Вкладка **Аналитика** (`GET /api/analytics`) показывает воронку, исходы предложений, частые причины отказов, ставки одобренных заявок и метрики SLA: долю ответов банка в срок, среднее и медианное время ответа, текущую очередь.
4. Нажмите **Провести скоринг**. Демомодель рассчитает оценку и, если запрошенные условия не проходят, предложит варианты: меньшую сумму на тот же срок или ту же сумму на более долгий срок. Нагрузка оценивается по базовой ставке 22%, а итоговая ставка зависит от балла: от 85 — 18%, от 70 — 20%, от 65 — 22%; ниже 65 баллов одобрить можно только вручную, под 26%. Одобрение и контрпредложение действуют 7 дней (`OFFER_VALID_DAYS`), затем получают статус «Предложение истекло»; банк может продлить предложение, в том числе истёкшее.
5. Выйдите и войдите как предприниматель. Посмотрите факторы решения и блок **Как получить одобрение**, затем сравните варианты условий по платежу и переплате и выберите один. У каждого варианта есть помесячный график платежей (`POST /api/schedule`). Заявку можно отозвать до принятия условий, а отклонённую или отозванную — изменить и подать заново.
6. После скоринга сотрудник банка может **одобрить или отклонить заявку вручную** с обязательной причиной. Автоматический результат сохраняется в поле `decision`, ручное решение пишется в `explanation.manual_override` и в историю событий.
7. Создайте новую заявку и запросите уточнение из банка, отметив нужные поля: поток, выручку, платежи по долгам, просрочки. Клиент заполняет только запрошенные поля, изменения попадают в историю, затем заявку можно оценить заново.
8. Перезапустите контейнер — данные сохраняются в Docker volume.

В графике платежей можно рассчитать досрочное погашение: сумма, месяц и что уменьшать (срок или платёж); показывается экономия на процентах.

**Демо-данные.** В кабинете банка кнопка **Заполнить демо-данными** (`POST /api/demo/seed`) создаёт 26 синтетических заявок с историей за последние дни: все статусы, нарушения SLA, истёкшие предложения, ручные решения, все ступени ставки. Их номера начинаются с `DEMO`; повторное нажатие пересоздаёт их, **Удалить демо-данные** (`DELETE /api/demo/seed`) удаляет только их, настоящие заявки не затрагиваются. Отключается переменной `ENABLE_DEMO_SEED=0`.

Для сценария одобрения уменьшите сумму до 1 млн ₽. Для сценария отказа включите просрочки и запросите большую сумму. Сброс отключён по умолчанию. При необходимости на локальной машине установите `ENABLE_DEMO_RESET=1` и выполните `POST /api/demo/reset` с банковским токеном.

## Структура

- `app/main.py` — FastAPI, SQLite или Postgres, валидированные команды, правила и история событий.
- `app/static/index.html` — интерактивный интерфейс двух ролей.
- `docs/architecture.md` — архитектура, границы, data model, state machine, API, тест-кейсы.
- `docs/openapi.json` — выгружаемая спецификация OpenAPI (также доступна `/openapi.json`).
- `tests/test_flow.py` — тесты сценариев.
- `docker-compose.yml` — повторяемый запуск и volume.
- `THIRD_PARTY_NOTICES` — компоненты и моки.

## Допущения

- Демо-ставка фиксирована на 22% годовых **не соответствует ставкам или политике Альфа-Банка**.
- Скоринг — детерминированные правила `demo-rules-v1`; система не претендует на оценку реального кредитного риска.
- Реестр компании, бюро кредитных историй, подписание договора и выдача денежных средств **не подключены**; данные клиент вводит самостоятельно, просрочки — синтетический флаг.
- Есть **только демонстрационное** разделение ролей по статическим токенам. Это не промышленная идентификация или полноценный аудит. **Никогда не вводите реальные ПДн.** Подробности в `docs/limitations.md`.
- В следующей итерации: авторизация ролей, отдельная таблица политик и проверок, экспорт решения, тесты конкурентных обновлений, rate limiting и метрики.

## Для жюри

Здесь важно, что действия банка реально меняют клиентскую заявку, а состояние и объяснение сохраняются. Дополнительные функции не заменяют основной e2e-процесс. Проект запускается без платных API и без доступа к корпоративной инфраструктуре.
