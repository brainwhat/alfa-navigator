# Границы применимости и технический долг

Прототип **не предназначен для промышленной эксплуатации и реальных персональных данных**.

- Одна синтетическая организация/пространство; нет мультиарендности и изоляции реальных клиентов.
- Демо-пароль, статические токены и хранение токена только в памяти страницы — учебное упрощение. Для реального внедрения нужны корпоративный IAM/OIDC, session management, RBAC/ABAC и аудит привязки субъекта к компании.
- SQLite и синхронные операции соответствуют одному демонстрационному экземпляру, не горизонтально масштабируемому банку.
- Скоринг — версия demo-rules-v1 на вымышленных порогах и условной ставке 22%; не является банковской политикой или статистически валидированной моделью.
- Локальная «проверка ИНН» — только заглушка; она не доказывает существование компании.
- Приём условий обозначает смоделированное подписание и выдачу.
- Сезонная модель — иллюстрация падения потока в 4 месяцах года, без фактических прогнозов.
- На публичном хостинге необходимо поставить TLS, сменить секреты и убрать демонстрационные подсказки пароля, ограничить частоту запросов и исключить использование реальных данных.
- Нет идемпотентного ключа для POST, DLP/шифрования данных на уровне приложения, секрет-хранилища и интеграционных тестов UI в браузере.
